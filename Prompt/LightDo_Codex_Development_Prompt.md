## 四、完整保留 QuietDo 的待办语义

只维护一份本地待办清单，至少保留稳定 ID、文本、完成状态：

- 新增：输入后按 Enter 或点击加号，去除首尾空白，拒绝空内容；新任务出现在列表顶部，输入框清空并保持可继续输入。
- 完成：点击完成按钮切换状态，完成任务显示灰色文字和删除线，保留原位，再次点击恢复。
- 编辑：双击任务文字进行行内编辑，Enter 或正常失焦提交，Esc 取消。中文 IME 组合期间的 Enter 只确认候选词，不得误提交任务；处理组合输入结束与焦点事件的顺序。
- 删除：悬停显示删除按钮，点击立即删除，不弹二次确认；提供键盘可达的删除入口，不增加回收站产品功能。
- 持久化：增删改、完成切换及设置修改及时保存，重启后恢复顺序和状态。
- 长文本自然换行，任务多时顺畅滚动，空状态简洁，不能因窗口收起、切换模式或重绘而丢失编辑内容。
- 每个表面都呈现同一份数据，设置窗口不是第二个待办视图。

不增加多清单、分组、标签、提醒、截止日期、重复任务、优先级、子任务、搜索、日历、账号、云同步、AI 助手等功能。可以优化工程可靠性，不借机扩展产品范围。

## 五、液态磨砂玻璃视觉

以 Glance 的玻璃主题为主要参考，接近 macOS 液态玻璃的轻盈感，同时保持 Windows 桌面上的可读性和操作习惯。

1. 使用真实背景参与渲染，包含柔和模糊、可见但克制的边缘折射、圆角厚度感、细腻高光、薄边框和自然阴影。
2. 每一个实际设计为独立玻璃块的面板都应具备对应边缘效果；不必把每一行待办都做成厚重玻璃卡片。保持极简层级。
3. 禁止用固定壁纸、预制背景、纯透明填充、渐变边框或仅 CSS blur 冒充真实桌面背景折射。普通透明或模糊效果只能作为明确标识的兼容降级，不能冒充完整效果已经验收。
4. 普通悬浮模式下，在面板后移动应用窗口或播放动态内容时，验证背景更新合理；桌面模式验证壁纸更换、窗口移动及窗口层级变化。区分真实背景采样和仅采样壁纸的行为。
5. 不使用频繁隐藏窗口再截图的方式制造可见闪烁；处理捕获自身、黑帧、缓存过期、设备丢失及采集失败。背景图像只在本机内存中使用，不落盘或上传。
6. 提供浅色、深色、跟随系统，默认跟随系统。只实现玻璃主题，不增加纸张和独立亚克力主题。
7. 提供玻璃透明度滑块。主要调整材质层，不把文字、图标和输入框一起变得不可读；范围、默认值通过实际效果确定并持久化。
8. 使用清晰的中文字体、统一图标、合理留白。所有交互具有 hover、pressed、focus 等必要反馈，键盘焦点可见。
9. 处理系统关闭透明效果、高对比度、减少动画、远程桌面和图形能力不足的情况：保证功能可用，并在设置或诊断中如实显示降级状态。
10. 使用测试壁纸和无隐私测试窗口制作真实运行截图或短视频，展示浅色、深色、背景折射及三种窗口形态，不用静态设计稿充当运行证据。

## 六、边缘自动隐藏与焦点管理

建立明确的窗口状态机，把停靠、展示、编辑、拖动等状态分开管理，避免零散布尔值相互冲突。

核心状态至少涵盖：停靠隐藏、展开中、已展开、收回中、固定展开、拖动或缩放中、普通悬浮、桌面组件。输入、菜单和对话框可以作为阻止自动隐藏的交互状态。

默认行为：

- 首次启动显示简洁的使用提示和可操作面板，说明“推向主屏右边缘呼出”；之后按规则进入自动隐藏，不出现启动后找不到软件的情况。
- 默认主显示器右侧，设置中可切换左侧。只开放主屏左右侧的停靠触发；不扩展到顶部、底部或多显示器边缘配置。
- 参考 Glance 的防误触逻辑：向边缘有意推动或停留才展开，快速掠过和常用滚动条操作尽量不触发；初始停留参数可取约 250 ms，最终以测试确定。
- 如果主屏边缘与另一显示器相接，用户仍可正常跨屏；不得锁住鼠标。用边缘停留等可行方式触发，并说明行为。
- 展开与收回使用平滑、可中断、可反向的动画，目标约 180–250 ms，不排队积累动画；适配系统减少动画设置。
- 鼠标离开整个交互区域后，默认约 400 ms 再收回；延迟内返回就取消。避免面板边界、阴影和关联菜单造成来回抖动。
- 编辑、输入法组合、候选词选择、菜单操作、对话框、拖动、缩放期间暂停自动收回。不得因暂停而永远卡在展开态，交互结束后按真实鼠标和焦点状态重新判断。
- 输入框有活动编辑焦点时保持展开；切换到其他应用后妥善提交已确认文本，并恢复自动隐藏。IME 未提交内容不可粗暴截断或误保存。
- 鼠标触发的初始展示不抢走前台应用键盘焦点；用户点击输入框后再正常获取焦点。明确区分展示与激活，不用全局模拟按键抢焦点。
- Esc 优先取消当前编辑或关闭菜单；无内层交互时关闭未固定的边缘面板。不要让 Esc 意外退出应用。
- 默认快捷键建议 `Ctrl+Alt+L`，支持修改；冲突时明确提示。快捷键用于呼出并进入可输入状态，已展开且无编辑阻塞时可收回。
- 提供“固定展开”开关：即使鼠标离开仍保持展开。它与“锁定位置”和“始终置顶”是不同概念。
- 默认在主屏全屏应用运行时暂停边缘呼出，快捷键仍可用。对独占全屏的限制如实说明，不承诺系统不允许的覆盖行为。
- 隐藏后不能残留透明矩形挡住其他应用点击，也不能占据桌面布局或推动其他窗口改变大小。

所有默认延迟是工程初值，不是要求照抄的魔法常量；提取为可维护参数，提供必要且简洁的设置。

## 七、同一面板的三种形态

### 1. 边缘面板

主屏左或右侧停靠；支持自动隐藏、固定展开、调整尺寸和切换停靠侧。保留舒适边距，不覆盖任务栏关键区域。明确处理系统工作区、物理屏幕边缘和 DPI 坐标。

### 2. 独立悬浮窗

从标题栏或明确拖动区域将面板拉离停靠边缘，转为独立窗口；支持拖动、缩放、锁定位置和“始终置顶”开关。默认普通非置顶，避免持续干扰其他应用。

拖到主屏左右停靠区域时显示清晰预览，松手后回到对应边缘自动隐藏模式。锁定位置时禁止拖动和缩放，但任务编辑仍可用。面板可通过菜单显式返回边缘模式，不只依赖拖动手势。

### 3. 桌面组件

允许将同一面板固定到桌面层，在普通应用窗口下面显示；回到桌面时可见、可添加和编辑任务。

必须验证 Win+D、再次 Win+D、桌面图标交互、资源管理器重启、锁屏与恢复、分辨率或缩放变化后仍正常。不得把普通非置顶窗口直接命名为“桌面组件”。

涉及非稳定系统行为时隔离封装，记录支持范围并具备恢复路径；不能出现组件永久失踪。桌面嵌入失败时明确提示并恢复可用的普通悬浮窗，不声称桌面模式成功。

### 4. 通用要求

- 三种形态共享同一个待办面板及数据，切换不产生重复窗口、重复保存或状态竞争。
- 提供合理的显示标题栏、锁定位置、置顶、固定展开、切换模式等入口；不适用的选项明确禁用或隐藏。
- 不强制移植 Glance 的甩动关闭、复杂变形、内容拆分等与单清单无关的交互。若提供鼠标穿透，必须默认关闭并有托盘或快捷键恢复方式；不作为首版必需项。
- 窗口模式、几何位置、尺寸和适用设置可恢复；恢复后保证窗口落在可见工作区。主屏更换或外接屏断开后不能丢失窗口。
- 对多屏环境只做安全定位和主屏识别，不增加多屏触发产品功能。

## 八、托盘、设置与日常使用

1. 常驻系统托盘，提供显示/隐藏、窗口模式、返回主屏、设置、开机启动和退出等必要操作。托盘行为应能帮助用户从隐藏或异常位置找回窗口。
2. 单实例运行，再次启动唤起已有实例，不新增重复托盘图标或同时写同一份数据。
3. 标题栏关闭按钮默认隐藏到托盘，并仅首次作简短提示；托盘提供明确的“退出轻待”。隐藏、自动收回和退出是三个不同操作。
4. 开机启动默认关闭，用户可在设置中打开和关闭；正常启动不要求管理员权限，不使用提权定时任务。
5. 设置包含必要项目：主题、玻璃透明度、主屏左右停靠、自动隐藏与延迟、防误触灵敏度、快捷键、全屏避让、当前窗口模式、标题栏、置顶、锁定、开机启动及恢复默认设置。组织清晰，不形成大型控制台。
6. 界面默认简体中文；英文品牌 LightDo 保留，不要求首版完整多语言。
7. 设置对话框、菜单和输入组件与玻璃主题协调，同时保证可读性和键盘访问。
8. 应用日常运行不需要登录、不联网、不上传数据，不加入遥测、更新轮询或后台自动更新；发布更新由 GitHub Releases 提供手动下载安装。

## 九、本地数据与可靠性

- 使用独立应用标识和独立数据目录，例如 `%APPDATA%\LightDo\`，在文档中写明最终路径。
- 不覆盖、删除或自动搬走 QuietDo 原有数据。首次启动可检测已知 QuietDo 数据路径并提供一次明确的本地导入选择；未选择不导入，导入是复制，保留源文件并避免重复导入。
- 数据结构有版本号；保存采用适当的原子写入、串行化和错误处理，防止截断、乱序覆盖和半写入 JSON。
- 删除任务保持 QuietDo 的即时删除语义；不保留包含已删除任务的长期历史或用户可见回收站。原子写入临时文件只用于事务安全，成功后清理，不当作恢复已删除任务的功能。
- 配置损坏、文件锁定、磁盘满或权限不足时明确提示；不得在读失败后悄悄写入空清单覆盖原数据。必要的损坏文件隔离保留须有说明。
- 正常退出、崩溃后重启、快速连续编辑、切换窗口模式等场景要验证数据完整性。
- 日志不记录任务正文、背景图像、凭据或多余个人信息；限制日志大小。

## 十、工程与性能要求

建议将待办模型、存储、设置、边缘触发、窗口状态机、玻璃渲染、文本输入、托盘和平台集成分为清晰模块，保持共享业务状态与具体窗口绘制解耦。

- 使用合适的系统事件、通知和按需重绘；隐藏后停止无意义的动画和背景捕获，避免高频空转轮询。
- 隐藏静置时目标为接近零 CPU，无持续 GPU 渲染负载；可将任务管理器进程 CPU 平均低于约 0.5% 作为参考目标，报告测试硬件与采样时长，不伪造跨设备保证。
- 动画目标流畅接近显示器常见的 60 Hz 更新节奏；按需刷新，不要求静止窗口持续满帧。
- 报告启动时间、隐藏及显示时的内存、CPU/GPU 占用、安装包大小；不生搬 Glance 的宣传数字。
- 检查 COM、GPU 纹理、窗口句柄、钩子、计时器和托盘资源的释放；反复切换模式不持续泄漏。
- 支持 Per-Monitor DPI 的正确定位与缩放，至少检查 100%、125%、150%、200%；主屏触发和窗口实际显示坐标一致。
- 锁定依赖版本，选择并说明最低受测 Windows 11 版本。若部分版本只能降级，明确列出，不笼统宣称所有 Windows 11 都完整支持。
- 没有必要不引入 Electron、大型前端框架、服务进程或后台常驻辅助程序。
- 不引入硬件监控、驱动、传感器服务、音乐、歌词、文件中转、剪贴板监控、快捷启动、手机远程、联网诊断等 Glance 业务与依赖。

## 十一、本机工具链与构建

先检查 Windows 版本、架构、PowerShell、Git、GitHub CLI、Rust stable MSVC、C++ Build Tools、Windows SDK，以及选定安装器工具。仅当保留 Tauri 时检查所需 Node.js 和 WebView2。

提供可复现脚本，例如 `scripts/dev.ps1`、`scripts/check.ps1`、`scripts/build.ps1`、`scripts/release.ps1`。命名可以调整，但开发、检查、生产构建、打包和发布的入口必须清晰。脚本保留真实退出码，任何构建或测试失败不得继续假装成功。

## 十二、EXE 安装包

1. 提供 `LightDo_<version>_x64-setup.exe`，使用稳定安装器方案，例如 NSIS，避免引入不必要的运行环境。
2. 默认按当前用户安装，适当创建开始菜单入口，提供可选桌面快捷方式；在 Windows“已安装的应用”中可以卸载。
3. 普通用户不应安装驱动或依赖管理员权限才能使用待办和玻璃效果。
4. 应用名称、版本、图标、发布者、可执行文件属性和卸载项一致。发布者使用我的真实 GitHub 身份或经确认名称，不冒用上游作者。

10. 从最终 Release 下载的安装包进行安装、运行、升级或卸载验证；环境允许时在干净的 Windows 11 Sandbox / 虚拟机中补充测试，不能冒充已经做过。

本任务授权你为本项目创建独立公开仓库、提交和推送源码、推送正式版本标签，并公开发布 Release；仅限本项目，不修改其他仓库或账号设置。

5. 配置提交/PR 的检查流程，以及推送正式 SemVer 标签如 `v1.0.0` 触发的 Release 流程。
6. Release 使用适合目标的 Windows x64 runner，设置明确工具链，先检查、测试和构建，再生成 EXE、SHA-256 校验文件及必要许可附件。发布只在全部必须步骤通过后发生。
7. 最终公开 Release 的 `draft=false`、`prerelease=false`；可以在内部先暂存产物，但不能留下公开却缺少安装包的“成功”版本。

9. 用于运行 GitHub Actions 的仓库令牌权限最小化；发布任务才需要 `contents: write`。不硬编码个人 Token，不向不可信 PR 暴露发布凭据。

11. 以后通过统一脚本完成版本更新、检查、提交与标签发布；脚本阻止脏工作区、版本不一致和重复标签。发布脚本不擅自改写已公开版本。
